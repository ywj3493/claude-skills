## 애그리거트 구조

<!--
`classDiagram`으로 애그리거트 루트, 엔티티, 값 객체와 그 관계를 그린다.
스테레오타입을 반드시 붙인다: <<AggregateRoot>> <<Entity>> <<ValueObject>>

**애그리거트 경계를 넘는 참조는 ID로만** 그린다. 다른 애그리거트의 객체를
직접 참조하는 선을 그리지 않는다. 실제 코드가 직접 참조하고 있다면 그
사실을 `## 애그리거트 상세`의 비고에 기록한다.

다른 도메인의 애그리거트는 여기 그리지 않는다 — domain-map.md의 일이다.
-->

```mermaid
classDiagram
    class Order {
        <<AggregateRoot>>
        +OrderId id
        +OrderStatus status
        +place()
        +cancel()
    }
    class OrderLine {
        <<Entity>>
    }
    class Money {
        <<ValueObject>>
    }

    Order "1" *-- "1..*" OrderLine
    OrderLine --> Money
```

## 도메인 이벤트

<!--
발행되는 이벤트와 그것을 구독하는 쪽. 도메인 경계를 넘는 이벤트는
domain-map.md의 통합 계약과 일치해야 한다.
없으면 이 섹션과 목차 항목을 삭제한다.

- `페이로드`: 구독자가 처리에 필요한 필드만. 애그리거트 전체를 싣지 않는다.
- `전달 방식`: 아래 다섯 값 중 하나, 또는 `미정`. 핸들러는 어느 방식이든
  트랜잭션 커밋 후에만 실행된다.
  `커밋 후 동기` / `로컬 비동기` / `메시지 큐` / `이벤트 저장소+포워더` /
  `이벤트 제공 API`
- `실패 시 처리`: 손실 허용 여부, 재시도 횟수·간격, 상한 후 처리(보류 목록,
  수동 처리), 순서 보장 필요 여부. 재시도하는 방식이면 상한과 상한 후 처리를
  반드시 함께 적는다 — 빠지면 구현 스킬이 `미정`으로 본다. 재시도하지 않으면
  "재시도 없음". 정하지 못했으면 `미정`.

`미정`은 "설계 시점에 정하지 못했다"는 뜻이다. 구현 스킬이 구현 전에

## 동시성 정책

<!--
애그리거트마다 한 행. 상태를 바꾸는 행위가 없는 애그리거트도 행을 두고
방식을 `없음`으로 쓴다 — 행이 없으면 "검토하지 않음"과 구분되지 않는다.
이 섹션은 삭제하지 않는다.

- `충돌 시나리오`: 두 사용자(또는 프로세스)가 같은 애그리거트를 동시에
  바꾸는 구체적 상황. 없으면 "없음"과 그 이유(예: 소유자 한 명만 수정).
- `방식`: `낙관적` / `비관적` / `오프라인 비관적` / `없음` / `미정`
  - 낙관적: 버전 비교. 충돌이 드물고 사용자가 본 화면 기준으로 수정할 때
  - 비관적: 한 트랜잭션 안의 행 잠금. 충돌이 잦을 때
  - 오프라인 비관적: 여러 요청에 걸친 잠금(편집 화면 열기 → 저장)
- `버전 전달`: 낙관적일 때만. `요청`(클라이언트가 본 버전을 보낸다 —
  api-interface.md 스키마에 버전 필드가 필요) / `서버 내부`(한 요청 안의
  읽기-저장 사이만 보호). 다른 방식이면 `—`.
- `잠금 한도`: 비관적이면 대기 시간 상한, 오프라인 비관적이면 잠금 만료
  시간. 다른 방식이면 `—`.
- `충돌 시 동작`: 사용자에게 보이는 결과(오류 코드). 오류 코드는
  api-interface.md `## 오류 모델`에 있어야 한다. 서버가 자동 재시도해야
  하면 횟수를 함께 적는다(예: "재시도 2회 후 409 ORDER_CONFLICT").

역방향: 버전 컬럼, 잠금 쿼리, 잠금 테이블·분산 락 코드를 근거로 쓴다. 찾지
못한 애그리거트는 방식을 `없음`으로 쓰지 않는다 — `근거`에
`없음 — 확인한 경로: <경로들>`을 쓰고 방식을 `미정`으로 둔다.
-->

| 애그리거트 | 충돌 시나리오 | 방식 | 버전 전달 | 잠금 한도 | 충돌 시 동작 | 근거 |
|---|---|---|---|---|---|---|
| | | | | | | |
