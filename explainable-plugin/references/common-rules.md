# 공통 규약

`explainable` 플러그인의 **모든 스킬**이 시작 전에 로드한다. 스킬 본문은
여기 있는 내용을 반복하지 않고 항목 번호로 참조한다 (예: `계약 3`).

---

## 1. 문서 환경 감지 (모든 스킬의 단계 0)

**다른 플러그인의 명령을 가리키며 하드 스톱하지 않는다.** 문서를 만들라고
부른 스킬이 아무것도 안 하고 멈추면 안 된다.

1. **`docs/config.yml`을 읽는다.**
   - 있으면 `source_language`를 쓴다. 질문하지 않는다.
   - 없지만 `docs/<언어>/specifications/`가 있으면 추론한다
     (`reference` 제외, 애매하면 사용자에게 묻는다). 진행하고 추론 사실을
     완료 리포트에 남긴 뒤 `docs/config.yml`에 기록할지 제안한다.
   - `docs/` 자체가 없으면 한 번만 묻는다:

     > 문서 구조가 아직 없습니다. 어떻게 할까요?
     >
     > 1. `docs/ko/specifications/`에 바로 생성 (기본)
     > 2. `/dev-docs:init-docs`로 전체 문서 구조를 먼저 초기화
     > 3. 다른 경로 지정

     선택에 따라 출력 디렉터리만 만들고 진행한다.

   - **동의 없이 `docs/config.yml`, 루트 `CLAUDE.md`, `.claude/rules/`를
     쓰지 않는다.** 이 경계가 두 플러그인의 조합 가능성을 지킨다.

2. **리뷰 모드를 확인한다.**

   > 진행 방식을 선택해 주세요.
   >
   > - `단계별` (기본): 각 단계 후 검토를 받고 진행
   > - `연속`: 전체를 한 번에 생성하고 마지막에 검토

### 역방향 스킬 추가 단계

역방향 스킬은 위에 더해 **분석 기준 커밋**을 확정한다. 이 값이 이후 모든
인용과 `link` 줄의 기준이 된다.

```bash
git rev-parse HEAD
git remote get-url origin
git rev-parse --abbrev-ref HEAD
git status --porcelain
```

저장소 URL은 `https://`로 정규화한다.

## 2. 실행 규약

이 규칙들은 스킬 계약의 일부다. 어느 모델이 실행하든 결과가 같도록 작업
방식을 명시한다.

1. **템플릿은 필수다.** 각 단계는 생성 전에
   `${CLAUDE_PLUGIN_ROOT}/templates/` 아래의 템플릿 파일을 읽는다. 없으면
   없는 경로를 보고하고 멈춘다. 기억으로 구조를 지어내지 않는다.

2. **입력은 디스크에서 다시 읽는다.** 대화에 내용이 남아 있어도 파일을 다시
   읽는다. 사용자가 단계 사이에 문서를 고쳤을 수 있다.

3. **ID는 부여하는 것이지 추측하는 것이 아니다.** 형식은
   `${CLAUDE_PLUGIN_ROOT}/references/planning-rules.md`의 ID 표를 따르고,
   한 문서 안에서 빈 번호나 중복 없이 순차로 매긴다. 다른 문서의 ID를
   참조할 때는 그 문서에 실제로 있는지 확인한 뒤 쓴다.

4. **리뷰 게이트를 문자 그대로 지킨다.** 단계별 모드(기본)에서는 각 단계
   후 멈추고 사용자 승인을 기다린다. 여러 단계를 한 턴에 몰아 처리하지
   않는다.

5. **확인한 경로만 보고한다.** 완료 리포트에는 디스크에 실제로 존재하는
   파일만 나열한다.

6. **병합 전용 문서는 자기 소유 섹션만 쓴다.** `README.md`,
   `architecture.md`, `infrastructure.md`, `glossary.md`, `domain-map.md`,
   `verification/test-spec.md`가 대상이다. `<!-- OWNER: -->` 마커로 표시된
   자기 섹션만 건드리고 나머지는 **바이트 단위로 보존한다**.

7. **`## 읽은 소스` 원장**은 역방향 전용이다. 순방향 스킬은 코드가 없어
   인용할 대상이 없으므로 템플릿에서 그 섹션을 제목까지 삭제한다. 순방향
   문서에 이 섹션을 넣고 싶어진다면 기존 코드를 문서화하고 있다는 뜻이므로
   역방향 스킬을 써야 한다.

8. **프레임워크는 감지하거나 사용자가 정한다.** 기본값(백엔드 4-Layered DDD,
   프론트엔드 FSD)은 제안하되 사용자 결정이 항상 우선한다. 정해지지 않은
   값을 임의로 채우지 않는다.

9. **미해결 항목이 남아 있으면 완료를 보고하지 않는다.** `citation-verifier`
   리포트에 `MISMATCHED`나 `UNSUPPORTED`가 남아 있는 문서, 패스, 전체 작업을
   완료로 보고하지 않는다.

## 3. 검증 루프

### 결정적 검사 (모든 스킬)

```bash
bash "${CLAUDE_PLUGIN_ROOT}/scripts/check-docs.sh" docs/<원본 언어>/specifications
```

보고된 문제를 전부 고친 뒤 다시 실행해 통과시킨다.

### 인용 검증 (역방향 스킬)

1. 생성한 문서마다 `citation-verifier`를 한 번씩 호출한다.
2. **수정 루프**: `MISMATCHED`와 `UNSUPPORTED` 항목만 고친다. 인용된 위치를
   다시 열어 주장을 고치거나, 인용을 고치거나, `[ASSUMED: ...]`로 바꾼다.
   **`MATCHED`와 `EXCLUDED` 항목은 건드리지 않는다.** 깨끗해질 때까지 다시
   호출한다.

## 4. 완료 리포트

모든 스킬이 아래를 보고한다. 스킬 고유 항목은 각 SKILL.md가 추가한다.

- 생성한 파일 경로 (디스크에서 확인한 것만)
- `check-docs.sh` 결과
- 생성하지 않은 문서와 그 이유
- 건너뛴 단계와 그 이유
- 다음 단계 안내

역방향 스킬은 추가로:

- 문서별 `citation-verifier` 최종 집계
- **미해결 항목 개수**와 그 목록

## 5. 문서 규칙

- 모든 문서는 한국어로 쓴다. 코드 블록, 파일 경로, 식별자, 스키마는 영어
  그대로 둔다.
- 기계용 토큰은 영문 고정이다: `[REF: ...]`, `[ASSUMED: ...; basis: ...]`,
  `MATCHED`/`MISMATCHED`/`UNSUPPORTED`/`EXCLUDED`, 그리고
  `FR-`/`NFR-`/`US-`/`AC-`/`UC-`/`SCR-`/`UF-`/`T-`/`FLOW-` 접두사.
- `## 문서 정보` 표는 문서 **하단**에 둔다. 상단에 메타데이터 블록을 만들지
  않는다. `분석 기준 커밋` 필드는 역방향이면 단계 0의 SHA, 순방향이면
  "해당 없음"이다.
- 날짜는 `date +%F`로 얻는다. 기억으로 쓰지 않는다.
- 내비게이션 링크는 `${CLAUDE_PLUGIN_ROOT}/references/document-order.md`를
  따른다. 생성하지 않은 문서는 체인에서 빼고 링크하지 않는다.
- 횡단 문서(`architecture.md`, `infrastructure.md`, `glossary.md`,
  `domain-map.md`, `README.md`)에는 이전/다음 내비게이션과 `전체 문서`
  인덱스를 붙이지 않는다.
- 모든 Mermaid 블록은 문법적으로 완결되어야 하고 다이어그램 종류 선언
  (`sequenceDiagram`, `flowchart`, `erDiagram`, `classDiagram`,
  `stateDiagram-v2`)을 포함해야 한다.
- 증거가 없거나 해당하지 않는 섹션은 비워 두지 말고 제목까지 삭제한다.
  빈 표는 "확인했으나 없음"과 "확인하지 않음"을 구분하지 못한다.
- 증거가 없는 카테고리의 문서를 아예 만들지 않는다.

## 6. 공통 경계 규칙

1. **한쪽이 없는 프로젝트** — 백엔드 없는 프로젝트에 `*-design-backend`를
   부르면 감지 단계에서 증거 없음을 확인하고 **빈 문서를 만들지 않고**
   "해당 없음"을 보고하고 멈춘다. 프론트엔드도 대칭.
2. **모노레포** — 도메인 식별 단계에서 도메인뿐 아니라 앱·패키지 경계도
   함께 확인한다. `GENERATED-BY` 마커의 `root:` 필드가 그 경계를 기록한다.
3. **에이전트 호출 상한** — 선별 후에도 대상이 도메인당 20개를 넘으면
   개수를 알리고 진행 여부를 확인한다. 조용히 잘라내지 않고, 제외한 항목은
   완료 리포트에 남긴다.
4. **메타데이터 갱신 주체** — `분석 기준 커밋`, `최종 수정일`, 버전 이력은
   문서를 실제로 쓴 스킬이 같은 단계에서 갱신한다. 갱신하지 않은 문서는
   완료 리포트에 포함하지 않는다.
5. **증거가 없는 도메인** — 도메인 목록에서 빼고 그 사실을 리포트에 남긴다.
6. **도메인이 하나뿐이면** `domain-map.md`의 컨텍스트 맵·횡단 흐름 관련
   단계를 건너뛰고 그 사실을 완료 리포트에 남긴다.
7. **`## 패턴 범례`는 고정 표다.** 그대로 두고 편집하거나 줄이지 않는다.
