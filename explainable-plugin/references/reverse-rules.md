# 역방향 공통 규약

`reverse-design-backend`, `reverse-design-frontend`, `reverse-planning`이
로드한다. `${CLAUDE_PLUGIN_ROOT}/references/common-rules.md`와 함께 쓴다.

---

## 1. 근거와 인용 계약

이 계약이 역방향 스킬의 존재 이유다.

1. **코드에서 직접 확인한 사실만 쓴다.** 추측하는 표현, "보통 이런 경우에는",
   프레임워크 관례로 빈칸을 채우는 것 모두 금지다. 읽지 않았으면 사실로
   쓰지 않는다.

2. **모든 주장에 인용이 붙는다.** `[REF: 경로:줄번호]` 또는
   `[REF: 경로:시작-끝]` 형식이며, 저장소 기준 상대 경로와 정수를 쓴다.
   "관련 파일 참조" 같은 모호한 표현, 산문 속 괄호 인용, 이번 패스에서
   `Read`/`Grep`으로 실제로 열지 않은 파일의 인용은 전부 금지다. 도구로
   확인하지 못하는 인용은 인용이 없는 것보다 나쁘다 — 주장을 지우거나
   `[ASSUMED: ...]`로 바꾼다.

3. **완결성을 위해 필요하지만 코드로 확인할 수 없는 내용**은
   `[ASSUMED: <추론>; basis: <실제로 본 것>]`을 인용 자리에 쓴다.
   추측을 확인된 것처럼 보이게 하려고 `파일:줄`을 지어내지 않는다.

4. **의도를 추론해야 하는 섹션**에는 문서 상단에 배너를 넣는다:
   "이 섹션은 코드에서 추론한 내용입니다 — 이해관계자와 확인이 필요합니다."
   그리고 항목마다 인용이나 `[ASSUMED: ...]`를 붙인다.

5. **모든 문서는 `## 읽은 소스` 원장으로 끝난다.** 그 문서를 쓰면서 실제로
   연 파일(부분만 읽었으면 줄 범위 포함)을 전부 나열한다. 문서의 모든
   `[REF: ...]`는 이 목록에 있는 파일을 가리켜야 한다. 재실행 시 원장을
   **누적**한다 — 이전 실행의 항목을 지우지 않는다.

6. **인용은 코드를 가리킨다. 문서를 가리키지 않는다.** 설계 문서(`.md`)를
   인용하면 검증기가 문서를 문서로 검증하게 되어 근거 사슬이 끊긴다. 다른
   문서는 `## 관련 문서`의 링크로만 등장한다.

## 2. Source-Linked 시퀀스 규약

시퀀스 다이어그램을 담는 문서(`design/backend/sequence-diagram.md`,
`design/frontend/render-flow.md`)에 적용된다.

- **참여자 소스 링크** — 참여자마다
  `link <별칭>: Source @ <저장소 URL>/blob/<브랜치>/<경로>` 줄.
  `<저장소 URL>`은 `git remote get-url origin`을 `https://`로 정규화하고,
  `<브랜치>`는 체크아웃된 브랜치에서 얻는다.
- **메시지별 근거** — 화살표 바로 다음 줄에 실제 `경로:줄번호`를 담은 `Note`.
- **근거를 지어내지 않는다** — 확인 불가한 흐름은 `Note` 대신
  `[ASSUMED: <추론>; basis: <근거>]`.
- **숨김 호출 그래프** — 흐름 섹션 끝에 `<!-- CALLGRAPH: ... -->` 블록.
  보이는 `Note`와 독립된 두 번째 근거이므로 `citation-verifier`가 둘을
  교차 대조할 수 있다.

**다이어그램을 먼저 그리고 근거를 나중에 채우지 않는다.** 호출 그래프를
먼저 추출하고, 그것으로 다이어그램·`Note`·`CALLGRAPH`를 함께 렌더링한다.

## 3. 재실행 정책

역방향 문서는 특정 커밋의 코드를 기술한 스냅샷이다. 코드가 바뀐 뒤 부분
갱신하면 낡은 인용과 새 인용이 한 문서에 섞여 `분석 기준 커밋`이 의미를
잃는다. 그러므로 **해당 도메인의 역방향 산출물을 통째로 폐기하고 새
코드베이스 기준으로 다시 만든다.**

대상 도메인에 이미 역방향 산출물이 있으면:

a. 저장된 `분석 기준 커밋`과 현재 HEAD를 비교하고, 인용된 파일 중 몇 개가
   바뀌었는지 확인한다:

   ```bash
   git diff --name-only <저장된 sha>..HEAD -- <인용 경로들>
   ```

b. **폐기 대상 목록을 전부 보여주고 확인받는다:**

   > `<도메인>`에 이미 역방향 설계 문서가 있습니다.
   > 저장된 기준 커밋 `<sha>` 이후 인용 파일 `<N>`개가 변경되었습니다.
   >
   > 역방향 문서는 특정 커밋의 코드를 기술한 스냅샷이므로, 부분 갱신하면
   > 낡은 인용과 새 인용이 한 문서에 섞입니다. 다음 파일을 폐기하고 현재
   > 코드 기준으로 다시 만들 것을 권합니다:
   >
   > `<삭제 대상 파일 목록>`
   >
   > 1. 폐기 후 재생성 (기본)
   > 2. 중단
   >
   > 다음은 폐기하지 않고 이 도메인 관련 부분만 갱신합니다:
   > `architecture.md`, `infrastructure.md`, `domain-map.md`,
   > `README.md`, `glossary.md`

c. **작업 트리가 clean하지 않으면 경고한다.** 되돌리기를 git에 맡기므로
   커밋되지 않은 문서는 복구할 수 없다:

   > 커밋되지 않은 변경이 있습니다. 폐기한 문서는 git으로 복구할 수
   > 없습니다. 그래도 진행할까요?

d. **확인 없이는 삭제하지 않는다.**

e. **폐기 범위**는 호출한 스킬이 정한다 (`reverse-design-backend`는
   `<도메인>/design/backend/**`, `reverse-design-frontend`는
   `<도메인>/design/frontend/**`, `reverse-planning`은 그 도메인의 역방향
   `planning/**`). 횡단 문서와 `glossary.md`는 폐기하지 않는다.
   `glossary.md`에서 코드에 없어진 용어는 지우지 말고 `상태` 열을
   `폐기됨`으로 바꾼다 — 지우면 다른 문서의 링크가 끊긴다.

f. 삭제 후 정상 파이프라인을 처음부터 실행한다.

**순방향 산출물은 절대 폐기하지 않는다.** 판별 기준은 `## 읽은 소스` 원장의
유무다 — 순방향 스킬은 이 섹션을 생성하지 않는다. 순방향 문서를 만났을 때의
처리는 `reverse-planning`이 소유한다.

## 4. 탐색 에이전트 호출 규약

`operation-tracer`와 `render-flow-tracer`에 공통으로 적용된다.

- **대상 하나당 한 번 호출한다.** 5~8개씩 묶어 병렬로 실행하고 묶음마다
  결과를 병합한다.
- **에이전트 결과를 코드 재확인 없이 렌더링한다.** 반환된 간선 목록 하나에서
  다이어그램·`Note`·`CALLGRAPH`를 **함께** 만든다. 그래야 셋이 구조적으로
  일치하고 `citation-verifier`의 양방향 검사가 통과한다.
- **별칭은 스킬이 재배정한다.** 에이전트가 준 별칭은 그 추적 안에서만
  유일하다. 여러 결과를 한 문서에 병합할 때 문서 전체에서 유일하고 일관되게
  다시 배정한다. 같은 파일이 여러 추적에 참여하면 같은 별칭을 공유하게 한다.
- **계층·FSD 라벨은 한 곳에서 온다.** 코드베이스 구조 분석 단계에서 확정한
  매핑을 모든 에이전트 호출에 넘기고, 다이어그램 라벨도 그것만 쓴다.
  대상마다 라벨이 달라지면 병합이 어긋난다.

### `status: PARTIAL` 처리 절차

1. **1회 재시도** — 종료 규칙과 매핑을 보강해 다시 호출한다.
2. 여전히 `PARTIAL`이면 해당 구간을 `[ASSUMED: ...]`로 표시하고
   `unresolved` 항목을 문서의 `## 미해결 항목`에 남긴다.
3. **완료 리포트에 미해결 개수를 명시한다.**
4. 에이전트가 아무것도 반환하지 않거나 스키마를 벗어나면 그 대상을 실패로
   기록하고 다음으로 넘어간다. **묶음 하나가 실패해도 전체를 멈추지 않는다.**

---

## 5. 역방향 서술 규칙

- **발견한 규칙 위반은 사실로만 기록하고 리팩터링을 제안하지 않는다.**
  허용 의존성 위반, FSD 규칙 위반 모두 마찬가지다. 규칙을 코드에 맞춰
  느슨하게 고치지도 않는다.
- **실제 구조를 먼저 기술하고 기준선과 대비한다.** 코드가 3계층이면 3계층
  이라고 쓰고 4계층으로 재분류하지 않는다. FSD를 따르지 않으면 따르지
  않는다고 쓴다.
