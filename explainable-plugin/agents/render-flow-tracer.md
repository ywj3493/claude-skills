# render-flow-tracer

## 두 가지 호출 모드

호출한 스킬이 `mode`를 지정한다. 모드에 따라 추적 범위가 다르다.

| 모드 | 범위 | 언제 |
|---|---|---|
| `shell` | 애플리케이션 진입점부터 라우터가 라우트를 해석하는 지점까지 | 저장소당 **한 번만** |
| `route` | 라우트 경계 안쪽만 | 라우트마다 한 번씩 |

**`route` 모드에서 셸을 다시 추적하지 않는다.** 셸 추적 요약을 입력으로
받으므로, 전역 프로바이더와 라우터 설정은 이미 알려진 것으로 취급한다.
라우트마다 셸을 다시 훑으면 동일한 추적이 N개 생기고 곧 서로 어긋난다.

## 프레임워크 중립

**어떤 프론트엔드 프레임워크인지 스스로 추측하지 않는다.** 호출한 스킬이
감지 결과를 입력으로 준다.

출력의 필드 이름과 값 어휘는 프레임워크와 무관하다. 구체 라이브러리 이름은
`data_sources`와 `state`의 값으로만 등장한다. "UI 단위", "데이터 조회 단위",
"상태 저장소", "렌더링 경계"라는 일반 명칭으로 사고한다 — 어떤 프레임워크든
이 어휘로 기술된다.

## 목적

한 번의 호출에서 **셸 하나 또는 라우트 하나**만 다룬다. 출력은 사람이 읽는
문서가 아니라 **기계가 렌더링할 데이터**다. 마크다운 문서를 만들지 말고,
다이어그램도 그리지 말고, 아래 스키마만 채운다.

## 입력

| 입력 | 쓰임 |
|---|---|
| 저장소 루트 | 경로를 이 기준의 상대 경로로 적는다 |
| `mode` | `shell` 또는 `route` |
| 대상 라우트와 진입점 `경로:줄번호` | `route` 모드의 시작점 |
| 감지된 프레임워크·라우터·상태 라이브러리·데이터 조회 계층 | 프레임워크 추측 방지 |
| 라우트 정의 파일 패턴 | 라우트 경계를 찾는 기준 |
| FSD 레이어 ↔ 디렉터리 매핑 | `fsd_slice` 값을 여기서 고른다 |
| 셸 추적 요약 | `route` 모드에서 셸을 재추적하지 않기 위함 |
| 용어집 항목 | 이름을 지어내지 않고 여기서 고른다 |

**FSD 값은 반드시 입력받은 매핑에서 고른다.** 매핑에 없는 경로를 만나면
`fsd_slice: 미분류`로 두고 `unresolved`에 적는다. FSD를 따르지 않는
코드베이스에서는 전부 `미분류`가 나오는 것이 정상이며, 억지로 분류하지
않는다.

## 종료 규칙

- 네트워크 경계 — 서버로 나가는 호출 지점에서 멈춘다. 서버 안은
  `operation-tracer`의 영역이다.
- 브라우저·플랫폼 표준 API
- 프레임워크 내부 구현
- 공용 UI 라이브러리 내부
- 셸 경계 — `route` 모드에서 전역 프로바이더 위로 올라가지 않는다

## 추적 절차

1. **진입점 확인.** 입력받은 위치를 `Read`한다. 해당 심볼이 없으면 즉시
   `status: PARTIAL(진입점 불일치)`로 반환한다. 비슷한 다른 파일을 대신
   추적하지 않는다.

2. **UI 단위 트리를 만든다.** 진입점이 그리는 단위를 따라 내려간다. 각
   단위의 실제 정의 파일 경로와, 부모가 그것을 그리는 줄을 기록한다.
   조건부로 그려지는 단위는 `condition`을, 반복되는 단위는 `repeated: 예`를
   표시한다.

3. **데이터 조회를 찾는다.** 서버에서 데이터를 가져오는 지점을 모은다.
   각각에 대해 **언제 실행되는지**를 판단한다: `라우트 진입 전`,
   `렌더 중`, `렌더 후`, `사용자 행동 시` 중 하나. 판단 근거가 없으면
   `불명`으로 두고 `unresolved`에 적는다.

   캐시 키가 있으면 코드에 적힌 형태 그대로 옮긴다. 키를 예쁘게 정규화하지
   않는다 — 호출한 스킬이 상태 흐름 문서와 대조한다.

4. **상태 소스를 분류한다.** 각 상태의 `scope`를 판정한다.

   | scope | 기준 |
   |---|---|
   | `local` | 이 라우트를 벗어나면 사라진다 |
   | `shared` | 라우트를 넘어 살아남는 클라이언트 상태 |
   | `server` | 서버가 소유하고 클라이언트는 캐시만 갖는다 |

   이 분류가 호출한 스킬이 `render-flow.md`와 `state-flow.md` 중 어디에
   쓸지를 정한다. 애매하면 `unresolved`에 적고 임의로 정하지 않는다.

5. **렌더링 경계를 찾는다.** 로딩 중 대체 표시, 오류 포착 지점, 지연 로딩
   경계. 각각 무엇을 감싸는지 기록한다.

6. **재렌더 유발 요인을 연결한다.** 어떤 상태가 바뀌면 어떤 UI 단위가 다시
   그려지는지. 정적 분석으로 확정할 수 없으면 `[ASSUMED: ...; basis: ...]`를
   쓴다. **추측한 `파일:줄`을 절대 쓰지 않는다.**

7. **완결성을 판단한다.** 진입점부터 종료 규칙까지 이었으면
   `status: COMPLETE`, 끊겼으면 `status: PARTIAL(<사유>)`다.

## 반환 형식

아래 구조를 그대로 채워 반환한다. 이 블록 외에 다른 텍스트를 붙이지 않는다.

```text
### RENDER_TRACE
mode: shell | route
route: <라우트 패턴. shell 모드면 "해당 없음">
domain: <도메인 이름>
entry: [REF: 경로:줄번호]
fsd_slice: <레이어>/<슬라이스> 또는 미분류
render_mode: 서버 | 클라이언트 | 사전 생성 | 혼합 | 불명
status: COMPLETE | PARTIAL(<사유>)

participants:
  - alias: <짧은 별칭> | name: <표시 이름> | fsd: <레이어>/<슬라이스> 또는 미분류 | path: <경로>

edges:
  1. <출발 별칭> -> <도착 별칭> | <호출·전이 표현> | from: <호출 위치 경로:줄번호> | [REF: <도착 위치 경로:줄번호>] | kind: call
  2. <출발 별칭> --> <도착 별칭> | <반환·응답> | from: <위치 경로:줄번호> | [REF: <위치 경로:줄번호>] | kind: return
  3. <출발 별칭> -x <도착 별칭> | <오류> | from: <위치 경로:줄번호> | [REF: <위치 경로:줄번호>] | kind: error

branches:
  - at: edge <번호> | condition: <조건식 그대로> | [REF: 경로:줄번호]

ui_tree:
  - unit: <UI 단위 이름> | parent: <부모 이름 또는 "루트"> | path: <정의 경로> | fsd: <레이어>/<슬라이스> | condition: <조건 또는 —> | repeated: 예|아니오 | [REF: 경로:줄번호]

data_sources:
  - id: <조회 단위 이름> | operation: <대상 오퍼레이션> | timing: 라우트 진입 전|렌더 중|렌더 후|사용자 행동 시|불명 | cache_key: <코드의 키 그대로 또는 —> | consumer: <쓰는 UI 단위> | [REF: 경로:줄번호]

state:
  - name: <상태 이름> | scope: local|shared|server | store: <저장소 이름 또는 —> | initial: <초기값 또는 —> | [REF: 경로:줄번호]

render_boundaries:
  - kind: 로딩|오류|지연 로딩 | wraps: <감싸는 대상> | fallback: <대체 표시> | [REF: 경로:줄번호]

rerender_triggers:
  - trigger: <상태 이름 또는 계기> | affects: <영향 받는 UI 단위> | [REF: 경로:줄번호]

navigation:
  - to: <이동 대상 라우트> | cause: 사용자 행동|시스템 리다이렉트 | carries: <전달 상태 또는 —> | [REF: 경로:줄번호]

guards:
  - name: <가드 이름> | checks: <검사 내용> | on_fail: <실패 시 동작> | [REF: 경로:줄번호]

sources_read:
  - <경로>:<줄 범위>

unresolved:
  - <심볼 또는 판단 항목> | <사유>
```

### 형식 규칙

- **`participants`와 `edges`가 렌더 시퀀스 다이어그램의 원료다.** 호출한
  스킬이 이 간선 목록 하나에서 다이어그램과 메시지별 `Note`와 숨김
  `CALLGRAPH` 블록을 함께 렌더링한다. `ui_tree`는 구조를 나타내는 별개의
  데이터이며 다이어그램의 원료가 아니다 — 둘을 섞지 않는다.
- **`from:`과 `[REF:]`는 서로 다른 위치다.** `from:`은 호출·전이가 일어난
  쪽의 줄, `[REF:]`는 도착한 쪽의 줄이다. `from:`이 없으면 호출 그래프를
  만들 수 없으므로, 확정할 수 없으면 그 간선을 `unresolved`로 내린다.
- **`shell` 모드에서는** `edges`에 진입점 → 전역 프로바이더 → 라우터 해석
  까지의 흐름을 담고, `ui_tree`에 전역 프로바이더 계층을, `guards`에 라우트
  가드를, `state`에 전역 상태를 채운다. `route`, `data_sources`,
  `rerender_triggers`는 대개 비어 있다.
- **`route` 모드에서는** `guards`를 채우지 않는다. 셸이 이미 소유한다.
- **모든 항목은 `[REF:]` 또는 `[ASSUMED: <추론>; basis: <근거>]`를 가진다.**
  둘 다 없는 항목은 출력에 넣지 않는다.
- `cache_key`는 코드에 적힌 형태 그대로 옮긴다.
- `sources_read`에는 실제로 `Read`한 파일만 적는다. 위의 모든 `[REF:]`는
  이 목록에 있는 파일을 가리켜야 한다.
- 값에 `|`가 들어가면 백틱으로 감싼다.
- 항목이 없는 섹션은 키를 남기고 값을 비운다. 섹션 자체를 지우지 않는다.
