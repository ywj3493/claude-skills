# Project Instructions

This project follows a structured documentation system. All work is driven by
and recorded in the `docs/` directory. Claude must treat `docs/` as the source
of truth and keep it up to date.

## Documentation Structure

Languages are configured in `docs/config.yml` — one `source_language` plus
zero or more `translation_languages`. New projects start with the source
language only (`translation_languages: []`); translation mirrors are added
later via `/dev-docs:sync-translations`. The tree below shows the `en` → `ko`
pairing once a `ko` mirror is configured; substitute the configured codes.

```text
docs/
├── config.yml            # Language configuration (source + translation languages)
├── en/                   # Source-language documents
│   ├── specifications/   # Domain-based: <domain>/requirements/ and <domain>/workflows/
│   │   ├── architecture.md, config.md, infrastructure.md  # Cross-cutting top-level docs
│   │   └── <domain>/     # Created by planning skills (e.g., auth/, dashboard/)
│   └── issue/            # One file per work item: issue001.md, issue002.md, ...
├── ko/                   # Translation mirror (only when configured; added by sync-translations)
│   ├── specifications/
│   └── issue/
└── reference/            # Reference materials — user-provided only, never generated by Claude
```

Operative working rules (commit messages, naming conventions, general
policy, the `@`-reference convention) live in `.claude/rules/` at the
project root — English-only, auto-loaded every session — not under `docs/`.

## Core Rules

1. **Start with an issue.** Every piece of work — feature, bug fix, refactor,
   investigation — begins by creating or referencing an issue — either a
   GitHub Issue (preferred when a remote exists) or a local document in
   the source-language `issue/` directory. Do not start implementation
   without one.

2. **Language directories.** Source documents live in the source-language
   directory (default `docs/en/`). Translations live in each translation
   language's directory with the same filename (no language suffix).
   Example: `docs/en/issue/issue003.md` → `docs/ko/issue/issue003.md`

3. **Translation mirror.** Every doc created under the source language's
   `specifications/` and `issue/` directories gets a matching
   translation in each configured translation language. Projects with an
   empty `translation_languages` list skip this rule; run
   `/dev-docs:sync-translations` to opt in to mirroring later.

4. **Reference is read-only.** Never create or modify files in `docs/reference/`.
   That directory is managed exclusively by the user. It sits at the `docs/`
   root because reference materials are language-neutral.

5. **Policy is law.** Operative working rules live in `.claude/rules/` —
   Claude Code loads them automatically every session, so there is no
   manual load step. Policy rules take precedence over general conventions.

6. **Keep docs current.** When implementation changes, update the relevant docs
   in the same commit or PR.

## Required Context

Working rules are in `.claude/rules/` and load automatically every session
— no action needed to bring them into context.

For active work, load the relevant issue from the source-language `issue/`
directory (or via `gh issue view <number>` for GitHub Issues) and follow
any `@`-references it contains.

## Issue Document Format

This format applies to local docs-mode issues.
GitHub Issues use the same sections in the issue body (without Status/Created fields).

Each issue document must contain:

- **Title** and brief description
- **Status** — Open / In Progress / Done
- **Background** — why this work is needed
- **Acceptance Criteria** — what "done" looks like (checkboxes)
- **Tasks** — numbered checklist of steps
- **Notes** — decisions and discoveries made during implementation

## Language Notes

- Code, variable names, file paths, technical identifiers: English
- Documentation in the source-language directory: source language
- Documentation in each translation directory: that language
- Code blocks inside translated docs remain in English
