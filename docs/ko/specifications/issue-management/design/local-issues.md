# 로컬 이슈 관리와 선택적 Orca 연동

## 배경과 결정 기록

출처: [GitHub 이슈 #60](https://github.com/ywj3493/claude-skills/issues/60).
2026-10-26 사용자가 원래 제안을 변경했다. 로컬 이슈 관리는 `explainable`에
두고, 같은 플러그인의 독립적인 선택적 스킬로 Orca 연동을 제공한다.
다른 플러그인의 참조 문서를 실행 시 재사용한다는 원래 이슈 조건은 이 결정으로
대체한다. epic/leaf 원칙을 차용해 독립적으로 배포하는 계약을 정의한다.
`orca-with-gh-issue`를 변경할 필요는 없다.

구현 계약은 `explainable-plugin/references/issue-rules.md`와
`explainable-plugin/references/issue-orca-rules.md`에 있다.

## 책임 경계

| 구성 요소 | 소유 범위 | 의존성 |
|---|---|---|
| `explainable:issue-local` | 이슈 파일, 계층, 선행, 규모, 생명주기, epic 표와 설정된 미러 | Python 3, git 선택 |
| `explainable:issue-orca-worktree` | 워크스페이스 생성, 부모 연결, 표시 이름, 요청한 에이전트 | 이슈 읽기 계약, git, 설치·실행 중인 Orca |
| `local-issues.py` | 읽기 전용 검사, 번호 후보, 명시적 공용 원본 등록 | Python 표준 라이브러리, register/locate에만 git |

연동은 이슈 생명주기를 변경하지 않는다. 이슈 관리는 gh나 Orca를 호출하지 않는다.
다른 플러그인 파일을 참조할 필요가 없다. 기존 기획·설계 스킬에서 자동으로
이슈를 만들거나 에이전트를 실행하지 않는다.

## 파일과 상태 결정

파일은 `docs/<source>/issue/issueNNN.md`에 두고 JSON 값의 YAML frontmatter를 쓴다.
원본 필드는 id, type, status, parent, blocked_by, size다.
상태는 Open, In Progress, Done, Cancelled다. Blocked는 종료되지 않은 선행에서
별도로 계산한다. 부모 관계는 자식이 소유하고 epic 표는 그 관계의 표시이며,
지정한 표식 사이만 다시 쓴다.

완료는 수용 기준과 기록된 근거 또는 근거로 기록한 사용자의 명시적 완료 지정으로
판단한다. 브랜치·PR·머지는 선택이다. 취소된 선행은 대기를 풀지만 수용 기준의
충족을 증명하지 않는다. 활성 자식이나 해결되지 않은 관계 오류가 있으면 epic을
완료할 수 없다.

frontmatter 없는 기존 이슈는 번호를 예약하며 명시적으로 전환하기 전에는
변경하지 않는다. 로컬 ID와 GitHub 이슈 번호는 별개다. 번역 미러는 설정된
언어를 따르며 issue-local이 관리한다. 커밋·push·머지·설정 스캐폴딩은 자동으로
수행하지 않는다.

## 공용 원본과 동시성

git 워크트리는 git common directory에 절대 경로의 원본 디렉터리 하나를 등록한다.
등록 파일은 추적 문서가 아닌 로컬 머신 메타데이터다. 원본이 다른 checkout에
있더라도 모든 동작은 해당 원본을 읽고 쓴다. git이 없으면 명시한 이슈 디렉터리만
있으면 된다.

원본 경로가 없거나 등록이 충돌하면 오류다. 원본 checkout을 이동·삭제하려면
원본과 등록 경로도 명시적으로 이전해야 한다. 번호 후보는 기존 형식의 파일명도
포함하며 999 이후도 지원한다. 후보는 예약이 아니다. 쓰기는 디렉터리의 배타적
잠금을 얻고 입력을 다시 읽으며 새 파일을 배타적으로 생성한다. 충돌하면 덮어쓰지
않고 멈춘다. 여러 파일 중 일부만 쓰일 수 있으며 그 파일을 보고하고 디스크에서
재개한다.

## Orca 계약

워크스페이스는 저장소·실행 호스트·이슈 ID·정규화한 원본 경로의 조합으로
식별한다. 원본과 ID를 comment에 기록한다. 외부 provider 연결 플래그와 파일
URL은 쓰지 않는다. 브랜치만 일치하면 GitHub 번호와 겹칠 수 있어 확인이 필요한
후보로 본다.

워크스페이스 부모는 이슈 부모를 따르고 git base는 검증한 저장소 기본 브랜치다.
원격이 없으면 로컬 기본 브랜치도 쓴다. 부모가 없으면 생성 전에 결정을 받는다.
기존 워크스페이스는 다른 에이전트 실행 없이 재사용한다. 에이전트 기본값은 없음이다.
생성·실행 실패는 자동 재시도하지 않고 부분 성공 여부를 조회한다.

## 검증

```bash
python3 -m unittest discover -s explainable-plugin/tests -v
python3 explainable-plugin/scripts/local-issues.py check --root docs/en/issue
```

원격 없는 epic과 leaf 두 개, 선행 해제, 조기 epic 완료, 기존 문서 보존,
다른 부모의 선행, 누락·순환 관계, 규모, 메타데이터, 999 이후 번호,
실제 git 워크트리 간 공용 원본과 명령 종료 코드를 검사한다. PATH 트랩으로
파일 전용 명령이 git·gh·Orca를 호출하지 않음을 검사한다.

실제 Orca 워크스페이스 생성과 모델의 스킬 실행은 별도 통합 검사다.
Python 테스트가 이 두 동작을 증명하지는 않는다.

## 프롬프트 작성 점검

사용자가 요청한 `prompt-triwizard`를 작성 참고로 적용했다. 생성 모드, 한국어,
도구를 사용하는 에이전트 용도, 관심사별 독립 XML 컨테이너를 사용했다.
저장소의 SKILL.md 패키징은 유지한다. 참고 스킬은 작성 도구이며 설치 의존성이
아니다. 목적과 쓰기 범위를 먼저 밝히고 동작별 규칙을 필요한 시점에 읽는다.
멈추는 조건은 미확정 결정이나 확인 가능한 실패다. 요청 범위의 되돌릴 수 있는
로컬 작업은 이어서 수행하고 워크스페이스 생성이 이슈를 자동 시작하지 않는다.

저장소의 프롬프트 점검표를 검토했다. 재시도 상한·초과 처리, 상태의 일관성,
호출자·읽기 입력 계약, 쓰기 전 값 확정, 공통 규칙의 명시적 예외, 필드·필터
일치, 기존 형식·누락 정보 처리, 수용 기준을 지어내지 않는 경계, 명명된 결정
게이트, 문서가 명확한 절 참조, 기본값과 값 누락 시 동작을 확인했다.
독립 모델 평가나 평가 점수는 주장하지 않는다.
